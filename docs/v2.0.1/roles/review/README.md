# V2.0.1 场景铺满：独立审查记录

审查日期：2026-10-28。角色：独立代码审查；本角色只修改本文件，不修改产品实现或存档。Leader 负责修复、实际界面验收与发行。

## 用户反馈与边界

V2.0.0 免安装版的简洁场景左右露出透明带，桌面底层文字透过来，观感异常。本轮修复场景随窗口尺寸铺满，并保持人物、浮漂、天气、交互热区和对话位置相互对应。钓鱼规则、金币、道具、天气来源、数据目录与已有存档不属于本次修改范围。

## 已确认的根因

- `src/index.css` 的 `.widget-main .pond-scene > svg` 强制 SVG 宽高均为容器的 100%；容器的高度来自纵向 flex 布局。
- `src/components/pond/Pond.jsx` 的外层 SVG 使用固定 `viewBox="0 0 1000 440"` 和 `preserveAspectRatio="xMidYMid meet"`。
- 当容器约为 612×208 时，meet 的缩放取高度，实际画面宽约 472.7px；两侧各约 69.6px 不被绘制。简洁场景容器背景是透明，因此底层窗口内容可见。
- HTML 人物/浮漂按钮、气泡与咬钩提示按容器百分比定位。即使在旧版 meet 模式，这些锚点也没有计入图像的留白偏移。因此仅将 meet 改成 slice 不能视为完整修复。

以上是源码与坐标计算结论；本角色尚未运行修复后的应用，不能当作视觉验收通过。

## 建议的最小正确修复

使用一套 cover 坐标变换，保持画面比例：`scale = max(containerWidth / 1000, containerHeight / 440)`。绘制画面与其交互热区共用相同缩放和居中偏移；天气、水面、人物、钓线、浮漂应一起变换。避免横向强行拉伸人物。

地点/天气来源、顶部状态等界面标签留在可见容器内。对话的锚点应映射到实际可见坐标，并限制可读区域，不能因画面上缘被裁切而丢失文本。咬钩时覆盖全场景的收竿按钮继续覆盖整个可见场景。

普通页面模式保持原始 1000:440 布局；挂件模式响应尺寸变化。若引入观察器，需在卸载时清理，避免每帧读取布局或更改游戏状态。

### R1：居中 cover 会裁掉部分水墨场景人物脚部（静态与数学复验关闭）

612×208 或等比例的 406×138 场景，居中 cover 的可见源坐标约为 y=50.05–389.95。水墨经典人物脚部在淮河约 y=404、东南 y=409、西南 y=399，因此会被裁出可见区域。626×224 的可见源坐标下界也仅到 y≈398.91。通用人物图像下界分别约 y=414/419/409，同样越界。

实现者已在 `coverScene` 增加 `safeBottom`，由场景的角色图像下界及浮漂位置（额外 12 源坐标的安全量）决定竖向构图，偏移仍限制在完全覆盖容器的区间。新增17场景下沿断言与可见天空内的日月避裁计算；天气的显示开关不变。新增计算和既有相关测试共32项，独立执行全部通过。本项数学及静态复验关闭，实际布局仍由 Leader 验收。

### R2：只按容器尺寸去重会丢弃换场景后的新构图（静态复验关闭）

第一轮 `useSceneViewport` 只比较宽高，当 `safeBottom` 因装备场景或到达新水域变化、而窗口尺寸不变时，会丢弃重新计算的 `top`。已通知实现者；实现者现将 `top` 纳入去重判断。effect 依赖 `safeBottom`、观察器清理以及新偏移更新的源码路径一致；本项静态复验关闭，仍需实际切换场景复验。

### 实际对白高度需观察

目前 `visibleBubble` 的最小底边锚点为52 CSS像素，顶部预留6像素，对应最多46像素的可见气泡高度。12px、1.45行高、两行与边框/上下padding合计约48.8px。已请 Leader 检查实际双行和较长到达对白是否被裁字。边界计算通过不能代替文字完整性检查。
