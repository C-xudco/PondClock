## 需求与验证方法

用户指出 V2.0.0 背景两侧没有填满。核验目标为两个现有挂件尺寸 **420×350 / 640×490** 下，场景等比铺满、人物脚和浮漂不被裁掉、点击热区对应画面、对白在可视范围内，并保留简洁/水墨及晴雨雪。

测试脚本只监听 `127.0.0.1`，向 IAB 提供真实 `build-desktop` 生产 HTML、JS、CSS 和本地图片。页面中两个 iframe 各自使用指定尺寸，不改变产品布局。先加载独立 mock `pondDesktop`：5000 金币、全部外观权益、领南测试出生地、手动天气；这些都是经当前 schema 校验的显式测试数据，存储仅在 iframe 内存中。环境网络 API 一律拒绝，CSP 仅允许本机来源；没有读取、复制或修改正式玩家存档。

实际检查通过浏览器公开 DOM 读取边界、SVG `getScreenCTM()`、渔翁/浮漂点上的真实按钮；通过实际生产商城、漫游按钮和点击对白验证交互。航程专用按钮仅对测试 iframe 的墙钟加 180001ms，未改变真实系统时间；实际购买1260金币机票后从领南飞到东南，余额5000→3740。此时间加速不代表真实82秒航程已等待。

## 诚实边界与过程修正

首个普通工具范围的测试服务器 `scene-cover-BV1woV` 无法被 IAB 访问，本机另一个受限进程访问也报套接字权限错误。随后经正常本机执行范围启动服务器，IAB即可访问；没有修改 ACL、防护、代理或网络设置。首次失败的空报告保留。

脚本最初以 `parseFloat(width)` 判断画布稳定，会把初始 `100%` 回退样式也当作就绪；后续用“重新记录画面”按钮采集了稳定 px 舞台。原始报告保留这些首帧，不当作最终证据；最终评估仅取实际1000:440舞台的稳定采样。脚本现已修为等待显式 px 宽度，检查交互热点、无滚动和12种不同组合，避免重复采样凑数。这是测试夹具的修正，没有产品重建。

这些结果是**真实生产渲染器的浏览器/mock检查**，不是新 EXE 启动、Windows 桌面透明合成、置顶、磁盘保存、安装器或真实IP/天气验收。没有将工具截图或 DOM 测量混称为原生应用通过。结束时关闭本轮测试 IAB 标签与仅本机服务器，保留证据文件交给 Leader。
