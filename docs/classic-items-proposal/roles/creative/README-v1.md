## 3. 功能与生命周期

### 密封饵盒

- 入口：“补充鱼饵 · +1份”，旁边保留“直接出售 · 30”。玩家二选一，不能既用又卖。
- 使用时必须在地面、物品uid仍存在、类型正确，并且鱼饵库存加1后仍是安全整数；失败不消耗物品、不增加库存。
- 一笔纯状态命令完成：移除该uid + `baitCount += 1`；保存确认后UI才显示成功。与出售并发由现有串行队列决定先后，后一个不能再处理已移除uid。
- **一份仍是当前规则的5次鱼类捕获**，不是立即送5条鱼；当前正在使用的 `baitLeft` 不刷新、不覆盖。饵盒只补库存，随后沿用自动启用下一份的既有规则。
- 可以连续使用多盒，每盒只加1份；没有新倍率状态或时间限制。断网、旅行、重启后库存照常保留；飞行中不能使用或卖出。
- 按当前商店120金币/份，使用是120金币的“库存替代价值”，不等于立刻获得120现金；直接出售30是明确的流动性选择。

### 漂流瓶

- 入口：“阅读漂流笺”；不是消耗型“打开抽奖”。同一瓶每次显示同一篇文字，阅读后物品仍在，仍可按12卖出。
- 捕获时在同一笔结果里固定 `originRegionId`、`noteId` 和 `noteVersion`。文案从该水域已经准备好的离线小池选择，走独立 `bottle-note` 随机通道并保存选择；重开、点击次数、旅行和天气变化不重抽。
- `noteId` 对应不可复用的静态文案；以后改稿要保留旧ID/版本内容。信笺只谈游戏景观与生活，不假称即时天气、现实人物留言或联网玩家来信。
- 阅读是纯UI行为，不派发资产命令，不扣物品、不发钱、不解锁、不增加使用计数、不推进随机种子、不写“已读”存档。可以反复读；离线、重启或换区后内容不变。
- 阅读在物品详情面板显示，不强占鱼讯/收竿/到达对白气泡。为本次微调保持统一入口，**飞行中“阅读”按钮也暂不可用**，库存和物品说明仍可看；抵达后照常读原来的固定内容，不为只读动作增加飞行例外。
- 卖出后该uid消失，不能再从物品栏读。没有新增永久信笺收藏册，本版不要求保留出售后的阅读入口。

例子（只作语气样例，整池仍待审批后写作）：“桥边的人说，钓不到鱼也能带一点晚风回去。”这类文字不会断言当前正在下雨或某种鱼今天必咬钩。

### 磨花指南针

- 入口：“看看便宜航线”，物品保留；也可以按18卖出。查看不消耗、无次数、无加成，不改变任何资产。
- **飞行中暂不可查**，提示“抵达后再规划下一程”；落地后以当前 `currentRegion` 为明确出发地，调用现有 `quoteRoute` 数据，不使用现实IP地区或物品原产地作为起点。
- 返回除自身外全部有效路线，按票价升序、飞行时长升序、目的地区域ID字典序稳定排序，显示前3条。页面标题必须写明出发地和“当前标准票价”。
- 查看可以包括未解锁目的地，因为它只是现有路线报价；不自动解锁、买票、选目的地、瞬移、降价或启动航程。也不追加机票折扣。
- 地点/航程改变时关闭旧报价详情，下一次重新按新起点查询。断网照常查本地网络图，读档或导入不额外产生奖励。

### 通用库存与七天规则

- 六种新物品都进入独立 `items[]`，捕获uid/序号/时间/水域延续现有规范；不进入鱼篓报价或鱼类图鉴。
- 飞行中全部主动拾物按钮（出售、开盒、读笺、查航线）统一禁用，库存与静态说明可查看。落地恢复，不额外发补偿或刷新内容。
- 本提案**不为道具增加七天失效**，固定卖价不随地区/重量/品质/秘籍改变。七天固定1仅继续用于鱼；不能用道具处理去刷新任何鱼的时间。
- 收藏/查看只消费已保存数据。出售移除uid与加金币同笔保存；饵盒使用移除uid与加库存同笔保存；存档失败保留旧状态，未知回执按原命令身份恢复，不换ID盲目重试。

## 4. 完整排他掉落表与频率

以下表是**每次成功收竿**的一次排他结果，分母10000，完整合计10000。不是在鱼掉落之后再额外抽道具。

| 结果 | 当前权重 | 建议权重 | 建议绝对概率 |
| --- | ---: | ---: | ---: |
| 鱼 | 9820 | 9420 | 94.2% |
| 破鞋 | 150 | 150 | 1.5% |
| 泡水手表 | 20 | 20 | 0.2% |
| 网红秘籍 | 10 | 10 | 0.1% |
| 锈铁罐 | 0 | 70 | 0.7% |
| 河蚌壳 | 0 | 60 | 0.6% |
| 渡口代币 | 0 | 30 | 0.3% |
| 密封饵盒 | 0 | 100 | 1.0% |
| 漂流瓶 | 0 | 80 | 0.8% |
| 磨花指南针 | 0 | 60 | 0.6% |
| **合计** | **10000** | **10000** | **100%** |

旧三种物品的绝对掉率保持；新物共4%，只从鱼的权重让出。总物品从1.8%变为5.8%，仍以钓鱼为主。相同成功收竿数下，鱼数量期望相对下降约 **4.0733%**，稀有鱼图鉴/鱼类保底的现实推进也可能略慢；这是趣味与鱼量的取舍，不能宣称所有东西都凭空增加。

按普通竹竿55–125秒、均值90秒，并假设每次鱼讯都立刻成功收竿，约40次/小时：

- 任一道具平均约17.24次成功收竿一次，即25.86分钟；任一新道具平均25次，即37.5分钟。
- 30分钟内至少见到一种新道具约55.80%，60分钟约80.46%。没有首件保底，不保证每半小时必出。
- 单件平均等待：铁罐约3.57小时，壳约4.17小时，代币约8.33小时，饵盒约2.5小时，瓶约3.125小时，指南针约4.17小时。

这些是理想换算，不含点击反应/判定窗口、错过、暂停，也不计算更高级竿、加速或实际长时间游玩；不能写成玩家实际获得时间。概率较低是桌面常驻应用的长期收集节奏，用户也可审批时要求更热闹的表。

## 5. 经济影响

[算术JSON](PROPOSAL_CALC-v1.json)和[可重算脚本](calculate-v1.mjs)只读取项目配置，在本角色目录写文档数据，不修改游戏。

- 六件新物全部直接卖，新增**毛现金**期望是每次成功收竿0.648金币，理想40次/小时是25.92金币。不能忽略同时减少的鱼。
- 若旧策略中每条实际鱼的平均当地成交价为F，其他规则不变，新表与旧表的现金差为 **0.648 − 0.04×F**／成功收竿。F=16.2时打平；高价鱼水域或装备下总现金可能略少。
- 只作普通品质、标准体重、当地立即卖的示例，12区条件平均鱼价约11.08–24.12，现金差约+0.2048到−0.3168／竿。不是包含品质、鱼饵、保底、秘籍、跨区或过期的完整收益模拟。
- 若饵盒全用于补饵，按现有120/份计，六种新物的“现金+鱼饵库存替代价值”毛期望是1.548／竿；**这不是现金收入，也没计算额外鱼饵带来的品质收益**，不能与上一条净现金混比。
- 没有赌瓶子、没有重复开盒抽钱、没有用道具修复七天过期鱼，避免增加无限利润链。

## 6. 实现前必须解决的兼容点

以下是读代码得到的实施清单，不表示已经改好：

1. 当前 `itemSalePrice` 把非破鞋/秘籍的其他类型默认当手表返回50；加入新物必须改成显式类型分派/注册表，未知类型拒绝，不能悄悄给新垃圾50。
2. 当前 `BucketPanel` 只有秘籍有使用按钮、手表有修理，其他类型默认出售。需按 `sell/use/read/routes` 能力生成入口，不能用“非手表就是能使用”这样的分支。
3. 当前 `LOOT_CONFIG.version` 同时参与旧秘籍buff校验。新掉落表建议独立 `lootTableVersion`；旧buff语义版本与修理概率不改，不能仅把version从1升2让未用完秘籍失效。
4. 建议由架构角色统一采用schema4承接新物品类型/瓶笺字段与本轮新人物包；原schema1/2/3原件先备份，旧鱼龄/物品uid/固定修表结果/秘籍资格与次数/金币/搭配/航程保持。未来版本仍拒绝覆盖；退回旧应用不能静默丢新物。
5. 新拾物的类型、uid、noteId、来源、grant和消耗资格在纯规则/校验器中约束；renderer不能注入“给多少饵”。只有饵盒新增消费路径，其他新物不引入持久倍率状态。
6. 掉落、鱼种、修表、瓶笺和对白继续分随机通道。已确认捕获结果永不按新表重抽；读档、旅行、换网络、查看指南针或阅读瓶子不推进掉落随机。主动改档/恢复旧备份的单机作弊不承诺彻底阻止。
7. 初始100金币与原有2份高级鱼饵不因本次升级再发一次；收集到的饵盒只按真实uid一次生效。
