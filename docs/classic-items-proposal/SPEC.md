## 3. 本轮六种新拾物

全部名称、概率、卖价和功能是**工程提案，待你审批**。保持拾物进入独立物品栏，不混入鱼图鉴；没有收藏点数、兑换商店或额外任务链。

| 新道具 | 每次成功收竿概率 | 直接卖价 | 功能与限制 |
| --- | ---: | ---: | --- |
| 锈铁罐 | 0.70% | 3金币 | 普通生活拾物，卖掉或留在库存；配一条轻松的拾物反馈 |
| 河蚌壳 | 0.60% | 8金币 | 可留作水边纪念；“留念”只是库存保留，不新增收藏册奖励 |
| 渡口代币 | 0.30% | 25金币 | 带捕获水域的短说明，卖掉或留念；不是机票券，不免费解锁或旅行 |
| 密封饵盒 | 1.00% | 30金币 | 可直接卖，或开一次增加**1份现有高级鱼饵**，即最多供之后5次钓到鱼使用；不立刻给5条鱼、不刷新正在用的余次 |
| 漂流瓶 | 0.80% | 12金币 | 读取捕获水域的一封固定短笺；可反复读、不消耗、不发奖；卖掉后物品移除 |
| 磨花指南针 | 0.60% | 18金币 | 只读列出当前出发地最便宜的3条航线及票价/时长；不折扣、不买票、不传送、不解锁 |

### 使用与保存约定

- **开饵盒**：先检查物品存在、未处理、落地状态和库存可保存；移除盒子与baitCount+1在同笔提交，失败不吞盒/不加饵。重复点击、重开、超过命令历史都不能重复开启。
- **漂流瓶**：捕获时固定`noteId`、文案版本和原产水域；阅读不抽新结果、不写存档，不通过刷阅读改变掉落随机。未知旧文案保留明确兼容说明，不能静默换成另一封。
- **指南针**：复用现有航线报价，按价格→时长→稳定地区ID排序，排除当前区取3条；列表只读且标明起点，旅行后重新查询自然变化，不需持久buff。
- 飞行期间暂停卖、开、读、查等主动按钮，库存与说明仍可看；不为读物另建飞行中例外。
- 新拾物不耗高级饵、不推进或清空鱼类保底，沿用现行非鱼规则。物品没有“鱼获保鲜”机制，也不享受或消耗网红秘籍。
- **鱼满168真实小时固定1金币**不变。新物品不能给鱼续鲜、洗捕获时间、改变市场倍数或叠加秘籍。
- 各物品按能力显示出售／开盒／阅读／查航线按钮，UI只调用已确认命令或只读查询，不自行发奖。

建议每个水域首批3封短笺，共36封，偏地方风景和轻松吐槽；不编造实时天气、未加入的鱼种或现实垂钓许可。铁罐、贝壳、代币也有短说明，避免只换名称没有生活感。[创意细节](roles/creative/README.md)。

## 4. 掉率与收益影响

仍用**成功收竿结果互斥**的一张表，分母10000；失败收竿不是掉落机会。一竿只出鱼或一件物品。

| 结果 | 当前权重/概率 | 建议权重/概率 |
| --- | ---: | ---: |
| 鱼 | 9820 / 98.20% | 9420 / 94.20% |
| 破鞋 | 150 / 1.50% | **150 / 1.50%，不变** |
| 泡水表 | 20 / 0.20% | **20 / 0.20%，不变** |
| 网红秘籍 | 10 / 0.10% | **10 / 0.10%，不变** |
| 六种新拾物合计 | 0 | 400 / 4.00% |
| 合计 | 10000 / 100% | 10000 / 100% |

整体物品由1.8%增到5.8%，平均约17.24次成功收竿遇到一件物品；新物品平均25次。这是平均值，**没有保底**。按理想平均90秒一竿、每次都成功作示意：一小时40次，至少钓到一件新物品的概率约80.46%，不是一定能得到；装备、错过鱼讯和实际操作会改变小时数。

保持原手表500试修、普通10–200、名贵1000–9999、千分之一恰好10000，以及秘籍三次鲜鱼+50%和七天规则，不借机改已有数值。

新增物品全部直接出售时，新增毛现金期望是每次成功收竿0.648金币，同时少4个百分点的鱼。如果该状态下每条鱼平均售价为F，简单差额为 **0.648−0.04F**；F高于16.2时，这个简算可能降低收入。饵盒开出鱼饵是库存用途，不能把120金币店价当现金收益。因而不宣称“加新道具必定更赚钱”。[计算记录](roles/creative/PROPOSAL_CALC.json)。

如果你希望更常见，可以提高新拾物到6%，但会进一步挤占鱼；本轮推荐先用4%，试玩后再评，不同时新增掉落保底。

## 5. 为什么仍要做一次受控迁移

**玩家看到的是小版本，内部也要保护旧档。** 新商品ID和新物品type会被旧schema3校验器拒绝，因此建议统一升schema4，一次完成目录扩充与可选赠礼；旧schema1/2/3原始字节先备份，再提交新快照。较旧程序遇到schema4应提示使用新版本，不能静默清空。

| 兼容点 | 审批后做法 |
| --- | --- |
| 旧资产 | 保留金币、鱼/物品uid、捕获时间/序号、图鉴、种子、饵余次、付费航程和到达水位；不重新抽已捕获结果 |
| 已购外观 | 原有ID不删不重用，白发新ID独立，赠礼/购买来源分开记录，免费恢复经典不扣款 |
| 旧秘籍与修表 | 新掉落表版本与秘籍/修理规则版本分开；旧buff版本1继续有效，旧手表结果/待修种子不重算 |
| 新掉落规则 | 只作用于升级后的新捕获；同一规则版本内的重试/未知回执仍按已接受命令和捕获序号恢复，不能改命令ID重抽 |
| 物品分派 | 显式价格/能力/状态表，不再把“不是鞋或秘籍”的所有物品都当泡水表卖50 |
| 失败与未知回执 | 同一保存事务提交移除/获得/金币，未确认时不假装成功；重读调和，无法确认则阻塞并提示恢复 |

这一版不增加新的长期倍率buff、跨天计时器或在线服务。白发包复用已有素材，经典小人复用原始SVG，避免为小改动换引擎或加新依赖。[独立监督与兼容风险](roles/review/README.md)。

## 6. 审批后分工与验收

同一版本分两个实施工作包：先恢复经典/白发可选，再加六种拾物；分别提交和检查，统一做一次schema4迁移与最终完整ZIP，不同时发布两套互不兼容的存档规则。

| 角色 | 责任 |
| --- | --- |
| Leader | 记录批准项、冻结接口、整合商城/物品UI、README/版本/发行 |
| 美术/渲染agent | 原版路径恢复、角色独立几何、雨具/积雪、持竿与落地 |
| 道具/存档agent | 权重/能力/命令、显式报价、schema4迁移、赠礼幂等与失败保护 |
| 创意agent | 36封稳定ID短笺、六种说明与语气，不在实现中追加未批准道具 |
| 独立监督/验收 | 源轮廓对比、概率算术、交易故障、旧档、真实UI与ZIP证据 |

至少验收：

1. 默认与真实1.1.1原轮廓逐项对应；两档窗口、两背景、12区、晴雨雪夜中脚落岸、手握竿、线随竿尖；没有第二个人/竿/线。
2. 免费minimal恢复经典；其他已购搭配不动；白发按所批A/B政策出现，购买不自动装备，重复载入不重复授予/扣费。
3. 枚举10000槽总和正确，旧三物品绝对掉率保留；新六种可得、命名和按钮一致，不耗鱼饵/鱼类保底。
4. 饵盒使用/卖出并发、双击、保存失败/未知回执不会双得；漂流瓶内容稳定，阅读和查航线不改资产/随机状态。
5. 七天鱼固定1、旧修表结果和秘籍剩余次数、已付航程、离线重启/导入/未来版本保护均保留。
6. 实际生产UI、普通最终EXE、完整ZIP资源一致性分别留证；真实联网/安装器升级卸载没测就继续标未测。

这些是**拟验收条件，不是已经通过的功能测试**。本轮只检查历史源文件、提案算术、文档链接与产品前后快照。
