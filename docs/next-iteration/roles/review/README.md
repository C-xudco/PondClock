## 3. 数据、事务与迁移审查门禁

以下是待审核的数据与事务方案；其中一次修理限制及其他新增数据边界均须用户审批，不能据此直接修改 schema 或玩法。

1. 先审批鱼获／物品的可区分记录模型（稳定 uid、kind、模板／物种 ID、来源、时间）；物品不填假鱼体长、品质或图鉴。
2. 表需记录未修／已尝试及持久结果、结果规则版本、关联操作身份；失败同样是已尝试，不能再修或再次付费。
3. 修理扣 500、更新表状态、确定结果须作为同一资产事务提交。金币不足、表已出售、飞行限制或保存错误不能留下半笔交易。
4. 随机结果在允许展示／重试前有可恢复凭据；采用持久意图、稳定物品种子或等价方案由架构审核。不能在 render、报价或 reducer 重试时重新 Math.random。
5. 同一命令与同一物品重复点击、回执丢失、重开、导出导入不得重抽／重复扣款。超过旧 128 条命令历史后，物品终态／已消费记录仍应防重做。
6. 真正落盘前失败是否可重试、如何沿用同一操作身份须明确；保存状态不明先调和 durable state，不用新命令 ID 猜测回滚。
7. 秘籍需持久化使用边界、剩余次数和效果版本；以已提交捕获顺序／序号判“使用后”，同毫秒不能只比较时间戳。
8. 冷却／情绪／抽句历史默认会话状态，勿混入资产档；音量／静音若跨重开保存，须进入正式设置模式及迁移。
9. 迁移保留旧 uid、鱼种、金币、鱼饵、图鉴、解锁、home／real／currentRegion、在途已付航程与有效时间；新增字段给安全默认值。
10. Web 与 desktop 共用校验和迁移规则；先备份再原子写新档。未来版本、损坏档、迁移中断保留原件，不以新空档覆盖。

## 4. 概率、收益与防重抽核对

修表的概率分母是**全部成功收取修理费的尝试**，不是修成功的表、不是名贵表，也不是仅在某地区的尝试。
互斥且穷尽的分支至少包含失败／普通／名贵／顶奖，非负概率总和必须精确为 1；顶奖分支仅产生 10000，其余分支绝不能也产出 10000。
当前策划候选权重为失败 400、普通 550、名贵 49、顶奖 1，共 1000；这是待审提案，不是用户已经确认的比例。
若且仅若失败残值为 0、普通整数 10–200 均匀、名贵整数 1000–9999 均匀，则毛期望为 `0.4×0 + 0.55×105 + 0.049×5499.5 + 0.001×10000 = 337.2255`。
该假设下扣修理费后的期望为 -162.7745；相较直接卖 50 的增量期望为 -212.7745。改变失败残值／区间分布必须重算，不用最高奖金额掩盖整体收益。
掉落候选为鱼9820／破鞋150／泡水表20／秘籍10，共10000；类别表与修表1000分母分开核验，均为待审核提案。若每块表都付费修理，单次掉落再到顶奖的联合概率为 `(20/10000)×(1/1000)=1/500000`，不能与用户指定的每次付费修理千分之一混淆。
鱼／杂物掉落类别、鱼种、品质、体型、修表、对白应有独立且有名的随机入口；“独立”不能只表现为函数不同却共用同一序列。
概率精确性优先用可枚举离散槽位与边界样本验证，补统计抽样；不能因为几千次模拟没见顶奖就判概率错，也不能仅凭一次中奖判通过。
抽取范围、上下界是否含端点、配置版本和重放输入须在台账记录；存档防误重抽不扩展为联网反作弊或防玩家主动恢复旧备份的承诺。

## 5. 秘籍与行为冲突

- 统一判定顺序：物品走物品报价；鱼先判七天过期，过期价始终 1；新鲜鱼再判是否使用后捕获及剩余次数，符合才 +50%并消耗一次。
- 最先售出的三条指**成交顺序**而非最先钓到的三条；使用前旧鱼、物品及按当前 Leader 口径的过期鱼均不耗次数。
- 使用与捕获同毫秒、排队交错、已有 pending CATCH 时使用秘籍，按命令提交顺序裁定；失败命令不取得使用资格。
- 批量卖出先冻结顺序（策划建议已保存 catchSequence 升序、uid稳定次序，待审核），在同一有效时刻逐条判定、逐鱼舍入再求和；与相同顺序的单卖结果一致。
- +50%推荐取 quoteFish 已舍入地区 price 后逐鱼 Math.round(price×1.5)，与策划一致且待审核；乘未舍入原始售价可能不同，批准公式必须唯一，不能只写“逐鱼舍入”。
- buff 预览不扣次数；出售、次数消耗、金币变更同笔保存；跨地区不刷新次数，重开／调和不重复消费或返还。
- “有剩余次数则保留新秘籍不消耗、不叠加；剩0再用”是Leader推荐待审方案；出售秘籍、修坏表残值、物品是否耗鱼饵／影响保底和捕获统计也须审批，不能默认开启。

## 6. 声音与对白触发

离线音效本地打包；缺文件、解码失败或自动播放被拒绝只降级声音，不打断钓鱼、保存或UI；标明是否真正播放，不能把 play Promise 发出当成功。
Leader推荐待审：仅 idle→bite 的新入态发一次；倒计时、rerender、静音切换、音量变化不重播。后台允许开关默认on，隐藏／最小化时新鲜有效的新bite按开关至多播一次；开关off则静默并消费事件。恢复不制造新入态，永不补播过期事件；音量35%及独立静音仍是提案。
保存失败／界面卡顿不让气泡虚报成功；音量／静音独立于 speech 文案。毒舌针对钓鱼行为，不变成持续辱骂；“不做武侠养成”仅是范围解释，具体语句由人工审阅风格、强度与小尺寸可读性。
有限随机池无法永久绝不重复；验收“随机且有历史去重、耗尽后受控重入、不固定顺序循环”，不承诺无限全新对白。

## 8. 审批、派发与交接

Leader 的 docs/team 应区分“收到用户消息／已通知角色／角色确认／等待安全交接／已合并／已验证”，记录需求版本和批准时间。
