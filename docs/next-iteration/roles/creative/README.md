## 2. 对白机制：事件先筛选，随机袋再挑句

- 语气上限：调侃“手速、耐心、空军、钱包”，不羞辱人格、不嘲讽现实地域，不因重复点击惩罚金币或鱼获。
- 范围提案是不扩展为武侠养成：不新增境界、练功、功法升级、战斗或签到修炼链；“网红修炼秘籍”作为幽默物品名，并不将用户要求解释为禁止武侠文案。
- 输入事件建议：IDLE、POKE、POKE_THRESHOLD、POKE_ESCALATE、CATCH_FISH、CATCH_ITEM、MISS、ARRIVAL_COMMITTED、SELL、REPAIR_RESULT、BUFF_USED。
- 情境标签建议：regionId、鱼种/品质、等待时长、旅行状态、连点阶段、最近对白 ID；天气另有 source 与有效期，禁止读取现实 IP 天气来冒充当前水域。
- 每条配置含稳定 lineId、event、regionIds、conditions、weight、tone；先滤不适用项，再按整数权重建洗牌袋，每抽一次移除对应票。
- 建议同类袋内权重为 1–3；最近 8 条全局 lineId、最近 3 条同事件 lineId 暂时排除，袋空后重建；历史都排完时依次放宽同类历史、全局历史，但仍禁连续同句。
- 权重袋只管理对白，不改变资产随机；可注入 RNG 与时钟，不能用固定数组轮播或靠“上一句索引+1”伪装随机。
- 小池可退回同事件通用句；只有一条可用且与上一句相同则暂不发言，不能强行重复。缺少地区素材时不编造本地知识。
- 建议上线前通用池每事件不少于 8 条、12 区每区不少于 4 条；下方 30 条用于审阅风格，并非完整上线语料。
- 原触发保留：闲置时最近 10 秒内第 5 次有效戳漂触发首次空军调侃；触发后只清该轮计数，不清连点情绪。
- 建议阶段：首次阈值=无奈；再累计一轮 5 点=轻微毒舌；第三轮及以后=短句上限，不无限加重语气。
- 建议距上次有效戳漂静默 45 秒后复位情绪与窗口；离开水域、进入飞行、导入/重新载入时复位临时连点状态。
- 建议普通戳漂对白最短相隔 6 秒，升级调侃最短相隔 8 秒；统计点击独立于发言，节流不吞首次阈值资格。
- 首次阈值可替换低优先级闲聊一次；鱼讯窗口、交易错误/保存错误优先，阈值句若等待超过 3 秒则舍弃，不在事后集中补播。
- 建议同一时刻只显示一个气泡；鱼获/脱钩 > 到达 > 连点 > 闲聊；持续沿用约 4.6 秒并尊重减少动态设置。
- 建议闲聊仍沿用原 35–75 秒随机间隔；后台暂停闲聊，不把恢复前台的积压次数逐条补播。

## 3. 到达与地方介绍的真实触发

- 仅接受已成功保存且发生实际地点变化的 ARRIVE 或 REAL_VISIT 结果；从 currentRegion 的渲染变化反推到达属于错误触发。
- ARRIVE 的 eventId 建议来自 travel.id；REAL_VISIT 来自 command.id；保存失败、早到的 ARRIVE、同地无变化 REAL_VISIT 均不发到达事件。
- GEO_VISIT 只识别/永久解锁现实地区，既不等于移动游戏角色，也不触发“到了这里”的感叹。
- 建议事务内记录 arrivalEventId/sequence；保存确认后向当前活跃订阅者发一次效果，不持久化待播队列。
- 引导、刷新、读档、导入只恢复状态与消费水位，不把历史到达重播；重复回执按 eventId 去重，真实新一次抵达仍可说新句。
- 恢复在途且确实尚未结算的旅行，后续新提交 ARRIVE 才能发一次新到达句；读档动作本身不触发。
- 每次真实到达在“地方感叹 / 景观描述 / 当地游戏鱼种介绍”中建议按 4:3:3 选类，再进对应随机袋。
- 景观文本依赖已批准场景元数据，不擅自新增地标事实；鱼种只引用现有 REGIONS.fish/FISH。开发规范中明确其为游戏鱼群信息，不承诺现实可捕性；玩家台词自然表达，不反复念“本游戏鱼池”等技术标签。
- 无有效天气时只谈景、鱼与心情；有效缓存只能称“缓存显示”，模拟天气只能称“画面里的雨雪”，不能说“当地现在就是……” 。

## 4. 咬钩音效提案

- 触发点是闲置进入新 bite 状态的一次边沿，绑定 biteEventId；每秒倒计时、重复渲染、重复订阅都不再次播放。
- 建议先用短促“咕咚”一种；也可批准气泡/咕咚按 1:1 随机，两个候选都要柔和、不突兀、不似警报。
- 建议时长 150–400ms、默认音量 35%、默认不静音、默认允许后台播放；设置提供音量 0–100%、独立静音与后台播放开关，音量 0 等效无声。这些默认值与开关均待审，批准后持久保存。
- 文件随包离线提供，不调用 CDN；未来交付资源需有来源/授权、格式、大小、峰值说明，建议合计小于 100KB。
- 浏览器先尝试在用户明确手势后解锁音频；自动播放被拒仅保留视觉鱼讯，显示一次可操作的开启提示，不循环重试或报错刷屏。
- 建议隐藏/最小化时，后台播放开关开启则对新鲜有效的新 bite 播一次；关闭则静默且不排队。恢复前台不补过期/已错过事件，系统暂停恢复不连续追赶，后台节流不能令过期 token 被误当新事件。
- 切区、起飞、读档、导入和卸载订阅取消旧 bite token；播放失败不影响钓鱼与保存，不把音频成功当作资产提交条件。
- Mock 必测：同 token 多次只调用一次 play；新有效 token 一次；隐藏且 background=true 一次、background=false 零次；静音/0 音量/过时均零次；拒绝 Promise 被处理；恢复无过期补播；卸载不播。

## 5. 掉落入口与早期经济（建议待审核）

一次成功收竿先抽“鱼或物品”一个结果，再只走该结果事务；不能既入鱼篓又给道具。物品独立 `items` 库存，不混入严格鱼类 `bucket`。

| 互斥结果 | 整数权重 / 10000 | 概率 | 未使用直接出售 |
| --- | ---: | ---: | ---: |
| 鱼（沿用当地既有鱼种/品质/体型抽样） | 9820 | 98.2% | 沿用 quoteFish |
| 破鞋 | 150 | 1.5% | **1 金币（用户指定）** |
| 泡水手表 | 20 | 0.2% | **50 金币（用户指定）** |
| 网红修炼秘籍 | 10 | 0.1% | 建议不可出售 |
| 合计 | 10000 | 100% | — |

- 先抽分支，鱼分支才抽鱼；杆/饵/最佳点击的品质加成不提升物品率。建议非鱼不耗高级饵，不增减/重置高品质保底，不记鱼类图鉴；仍消耗本次等待与有效收竿。
- 现有鱼基价有白条 2、鲫鱼 4，地区/重量/品质会改变实价；设成功鱼获的平均当地新鲜售价为 F，此表即时直卖均值为 `0.982F+0.015×1+0.002×50=0.982F+0.115`。
- 低价 F=2 时为 2.079，比纯鱼 +0.079（+3.95%）；中价 F=10 时为 9.935，比纯鱼 −0.065（−0.65%）；秘籍暂按即时收入 0，未来收益需另算。
- 简化长期例：每本都完整加成 3 条售价恒为 F 的新鲜鱼、F 为偶数且不丢弃，则秘籍每次掉落机会另贡献 `0.001×3×0.5F`；F=2/10 时总均值分别为 2.082/9.95。这不是含地区、装备、保底、旅行、过期与修表选择的全经济验证。
- 默认约 55–125 秒鱼讯、平均按 90 秒粗估，手表均 500 次有效收竿一只，约 12.5 小时；挂机漏鱼、装备、飞行都会改变，不能承诺固定时间必出。
- 掉落率不随破产、修表失败或重开界面补偿；不以物品掉落频繁提供 50 金币，避免压过起始 100 金币和低价鱼的节奏。

## 6. 泡水手表：仅一次修理的完整概率与期望

用户明确数值：未修卖 50；修理花费 500；普通卖 10–200、名贵卖 1000–9999、顶级恰好 10000；每次已支付修理的顶级概率恰为 1/1000。仅修一次、失败率 40%、失败残值 0 均为下述待审策划规则。

| 修理互斥结果 | 权重 / 1000 | 概率 | 条件售价分布（含端点） | 条件均价 |
| --- | ---: | ---: | --- | ---: |
| 失败 | 400 | 40% | 建议报废残值固定 0 | 0 |
| 普通 | 550 | 55% | 10–200 的 191 个整数均匀抽样 | 105 |
| 名贵 | 49 | 4.9% | 1000–9999 的 9000 个整数均匀抽样 | 5499.5 |
| 顶级 | 1 | 0.1% | 固定 10000 | 10000 |
| 合计 | 1000 | 100% | 顶级不从名贵内二次抽奖 | — |

- 普通与名贵先选互斥分支，再在该区间等概率抽整数；取值 201–999 永不出现。顶级只能占总表 1 个权重，故 `P(10000｜已支付一次修理)=1/1000`。
- 手算期望毛收益：`0.4×0+0.55×105+0.049×5499.5+0.001×10000=337.2255` 金币。
- 扣 500 的净期望为 `337.2255−500=−162.7745`；相对直接卖 50 的机会成本后增益为 `337.2255−500−50=−212.7745`。
- 非负盈利不是目标；这是有亏损风险的趣味选择，不是刷钱引擎。重修、拆回未修、失败返还 500、重复抽取都不允许。
- 余额不足不扣钱也不抽；有效修理把扣款、固定结果/售价、`repairAttempted=true` 一起保存。未知保存回执先重读，同 command/item 不能重抽或重扣。
- 修好后售价固定，与地区、重量、七天鱼类保鲜、秘籍均无关；失败后建议变为已修失败物品，可按残值处理且永不能修第二次。

## 7. 网红修炼秘籍：后捕获、先卖出的三条

- 使用时原子移除该物品并记 activationCatchSequence；仅序号严格大于该边界的后续新捕获鱼可候选，使用前旧鱼、任何物品都不计。
- 推荐对仍新鲜候选按实际成功出售顺序消耗最多 3 个名额；单卖由玩家选择鱼，批卖按下述稳定顺序，不由系统自动挑最贵三条。面板显示“剩余 3/2/1/0 条”。
- 新鲜候选按出售地区的普通新鲜鱼价加 50%；“普通”指未加秘籍的原有品质/重量/地区售价，不把稀有品质改为 common。
- 建议先取得统一 quoteFish 已舍入的新鲜 price，再逐鱼 `Math.round(price×1.5)`；例如原价 3→5，两条共 10，不能先合并为 6 再乘成 9。
- 七天到期先判，恰好 168 小时起仍只卖 1，不能乘成 2；推荐过期鱼不加成、不耗名额，使用前旧鱼/物品也不耗。这是“前三条合格新鲜鱼”的待审解释，不冒称用户已确认。
- 可选语义：若用户更愿严格按“前三条后捕获已售鱼”计数，过期也占名额但仍 1 元；仅列待审核备选，主方案和验收按上条推荐口径。
- 批卖建议按已保存 `catchSequence` 升序、uid 作稳定次序；与按此顺序逐条单卖结果一致。同一原子批卖里及时递减次数，第 4 条不加成。
- 建议不叠加、不覆盖、不增加当前额度：有剩余次数时再次使用提示原因，第二本保留；用尽后才可用新一本，新边界不追溯覆盖上轮已捕获未卖鱼。
- 重开/导入保留 activation 边界、剩余次数与鱼序号；重复出售/使用命令幂等，重复命令与缺失 uid 不扣次数。导入旧快照是恢复备份，不承诺单机防回档作弊。
- 每次出售金币、移出鱼篓和剩余次数必须同一事务；保存失败不显示已获加成，恢复后不重复结算。无期限到期提案，只有三次额度。
- 可选趣味道具（非用户硬需求，不自动排期）：“防空军奖状”只解锁一句自嘲；“漂流便签”只给地方短句；“褪色明信片”只收藏场景文字，不新增产金倍率。

## 8. 未来模块与存档接口建议

- `dialogueCatalog` 负责语料/标签/权重；`dialogueDirector` 负责筛选、袋、历史、优先级与节流；`biteAudio` 负责一次事件、音量、静音、后台播放开关和播放失败隔离。
- `lootRules/itemRules` 负责唯一掉落表、一次修理表与结果；`market` 继续统一鱼价/保鲜/逐鱼舍入；`gameState` 负责物品/鱼/金币/次数的纯命令原子变化。
- `gameSession` 负责串行提交与保存后效果回执；hook 只适配输入与显示，不在音效/对白回调内结算、不自行重抽丢失回执的随机结果。
- 随机结果要与一次收竿 token/修理 command 绑定；重试复用结果。仅依赖既有最近 128 个 command ID 不足以长期防重，需持久单调事件边界或已结算记录，拒绝旧捕获重新入库。
- 建议 schema 1→下一版：`items[]`（uid/type/status/repairAttempted/fixedPrice）、`catchSequence`、鱼的 `catchSequence`、`saleBuff`（activation/remaining/sourceItemUid）、到达消费水位、音量/静音/后台播放开关。
- 迁移旧鱼按既有捕获时间与 uid 稳定赋序，全部早于后续激活边界；空物品、无 buff、音量/静音/后台开关默认值不改变旧资产。严校验整数金币/次数、唯一 uid、合法状态、跨字段一致性，拒绝未来 schema 并保留备份。
- 建议验证接口：可注入 RNG 的 `rollLoot/resolveRepair`、纯 `selectDialogue`、统一 `quoteSale`、持久命令结果/去重检查；函数名仅交接草案，不是本轮新增导出。
