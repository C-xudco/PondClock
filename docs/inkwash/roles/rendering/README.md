## 4. 数据输入与双轨天气

`game.currentRegion → SceneDefinition → SceneSite → sceneWeatherVisualState → Pond` 是唯一场景选择链；Pond 同时接收对应的定义与地点。出发至抵达保存提交前保留出发地和在途语义；抵达后才更换景点及其天气，切换时清理旧景视觉事件。
顶部 IP 现实天气另轨，设置 `viewer` 只改变查看目标；两者都不传进场景 selector。查看未解锁区也不能切景、解锁或写资产。地点、天气来源及更新时间由上层提供，渲染不伪造“当地实测”。

`WeatherEntry` 管 targetKey／generation／请求状态，`WeatherSnapshot` 管原始天气事实；viewer 订阅同一个 scene 条目。绘制层不创建另一套缓存或定时刷新器，也不自行用旧地点结果填补新景。
SceneSite 未核实坐标时保持 pending，渲染接受上层明确标记的未配置／模拟状态；不能为了展示真实天气向供应商试猜坐标。

与架构／天气角色协调后，消费结构为：

| 统一视觉字段 | 渲染用途 |
| --- | --- |
| `sky.coverage / sky.fog` | 云量层、雾层与墨色空气透视 |
| `celestial.sunVisible / moonVisible / starsVisible` | 日月本体、光晕与星点共同按状态绘制 |
| `celestial.reflectionVisible / directLightVisible` | 对应日月倒影、碎光、直射光与暖色光柱门控 |
| `precipitation.kind / intensity / basis` | 雨雪类别、视觉密度及强度依据；不从缺失值杜撰观测量 |
| `waterResponse` | `none`／`rain-impact`／`snow-dissolve` 的接触响应 |
| `fisherman.rainGear / snowTarget` | 蓑衣显隐及积雪表现目标 |
| `daylight.isDay / basis`、`quality` | 日夜依据与 complete／partial／legacy／simulated 质量；来源标签另取 Snapshot／Entry |

本文不另定义这些字段的枚举或 provider 阈值；最终细节随架构契约冻结。原始天气 code 由 WeatherSnapshot 保留。未知强度使用明确的保守视觉档，不能把一套粒子数量描述成真实“小雪毫米数”。

## 5. 图层、共享坐标与素材边界

逻辑画布固定 `viewBox="0 0 1000 440"`；1000×440 是场景而非整窗。各景可有独立 horizonY／岸线，当前 HORIZON=170 只是旧基线。图层、碰撞、雪盖、钓线与热点都从同一几何 ID 解析。

公共 SceneDefinition 只有 `geometryId` 引用，不另加 `geometries`／`anchors` 字段。该 ID 在渲染内部解析出 water-mask、hit-test、岸体／遮挡和 anchors，同一版本同时供绘制、接触与热点使用。
新增或修改几何时，资源母版、mask、姿态支点及截图夹具一起升级；不得让新岸线继续配旧水域判定。

| 自后向前的层 | 约束 |
| --- | --- |
| 纸感、天空、云雾、日月星 | 天气可独立关闭；纸纹受场景裁切，不把透明桌面填成纸矩形 |
| 远山／远林、中景地标、远岸 | 远淡近浓，地区轮廓独立；不能含固定太阳、人物、降水或晴日光柱 |
| 水色、轻纹理、环境反射、事件水纹 | 统一 water-mask 裁切；环境细波与雨雪接触效果分别管理 |
| 岸体／坐石、人物后衣片、身体／前衣片／斗笠 | 局部遮挡可拆；身体纸白是形体，外部背景须真透明 |
| 竿、钓线、浮漂、前景植物、天气前后层 | 按真实遮挡关系排序，人物和漂周围保留低细节区域 |
| 对话、地点天气标签、鱼讯与点击反馈 | 由程序绘制文本与交互；不能烘焙到图片中 |

采用**本地位图水墨纹理 + SVG／程序几何**混合：位图适合干笔、积染、飞白、纸纹及获审景物块面；SVG／程序适合可变岸线、mask、锚点、竿线漂、太阳门控与动态雨雪。两者不是二选一。
不要求照片静态底图，也不预设新引擎。不能用整张风景画盖住玩法；不能靠整屏昂贵噪声滤镜模拟全部笔触。先沿用现有 SVG／React 与浏览器能力，新增依赖须说明用途、包体、维护及性能预算。
未来确需 AI 位图创作时，应先读取并遵循当时可用的 `imagegen` 技能，使用其图片生成工具与参考图工作流；本轮不造占位图、不以程序随机纹理冒称已完成 AI 美术。
素材按美术清单的同一原点、比例、版本交付，建议母版 2000×880；透明 PNG／sRGB 为交接基准，发布格式压缩另测。纹理、字体和图片均本地打包，离线不依赖 CDN。
每景资源清单关联 regionId／sceneId／geometryId、层序、逻辑与像素尺寸、mask、锚点、来源／生成记录、hash、字节数及评审状态；所有 SVG defs／clip／filter ID 需按实例唯一。

## 6. 水陆遮罩与真实落点／时序

- 每景定义水域、岸／岛／桥墩等非水域，以及前景／人物遮挡。water-mask 的白色允许水面效果、黑色禁止，灰边仅抗锯齿；不能用 `y > horizonY` 或透明纹理 alpha 猜水陆。
- 几何判定与可见裁切必须来自同版数据；位图 mask 可配同源可查询栅格／路径。不得独立手写一份近似岸线供粒子使用。浮漂 surfaceY 必须落在该景有效水域内。
- 先在有效水域选定接触点或计算轨迹首次接触，再从粒子轨迹得到最终 `x/y` 与 `hitTime`；风偏或透视缩放变化后重算同一端点，不能随机另选一个水圈位置。
- 内部接触事件至少关联 particleId、scene／geometry 版本、kind、x/y、hitTime、强度依据与 seed。它是渲染内部记录，不新增共享天气 DTO 或存档字段。
- 单一视觉时钟驱动粒子到达和响应年龄：上一帧未到、当前帧越过 hitTime 时只发一次事件。掉帧也按跨越判定，不能依赖 CSS animationend 与另一个独立循环碰巧对齐。
- 接触水面后结束空中粒子；落岸／屋顶／人物的粒子不能生成水圈。水面效果先按水域裁切，再被当前人物和前景遮挡，避免水纹画上帽子、岸石或桥面。
- 切天气后旧事件在有限寿命内淡出，切 scene／geometry 后立即丢弃不匹配事件。卸载、最小化和恢复规则明确，不把旧雨存量带到新晴景无限叠加。

推荐把降水和接触响应放进同一 SVG 坐标树；若保留 HTML／Canvas 粒子，必须共用 SVG screen CTM／容器映射，计入 preserveAspectRatio 留边与 DPR，禁止再用独立百分比位移猜落点。

## 7. 雨、雪及阴雪天空

| 条件 | 空中运动与水面响应 | 人物／天空约束 |
| --- | --- | --- |
| 雨 | 较快细笔雨线；到达 hitTime 后同点短促撞击，再扩张为透视椭圆并淡出；尺度随水面深度变化 | 斗笠与独立蓑衣可辨；帽檐滴水若加入也走接触逻辑，不能预画固定岸边圆圈 |
| 雪 | 低速飘落、少量横摆；触水时在同点缩小／溶散并淡出，结束轨迹 | 帽顶与肩面雪盖贴合；不复用雨的强撞击圈，不能把白雨线改名雪花 |
| 阴天小雪 | 云层、低对比冷墨与轻量雪，强度来自统一视觉状态 | 太阳本体、光晕、地平线直射暖光、太阳倒影／碎光一起关闭；月星遵同一遮蔽规则 |
| 混合／未知 | 首批保留mixed／unknown及原始来源，waterResponse=none，不生成混合接触效果 | 遵统一保守天空门控，不把回退说成已实现混合降水物理 |
| 晴／雪停 | 不生成新雨雪接触；旧效果按上节清理 | 可按视觉状态恢复日照；积雪按选定视觉过渡消退，不决定真实积雪厚度 |

门控由同一 WeatherVisualState 发出，SkyLayer 与 WaterLayer 不各自猜天气；环境散射天光可以保留，但不得残留晴日光柱或伪装成月光反射。所有纹理也需人工查固定太阳／反光残留。
雪不等于永久冰封。首批保持可钓水面，不因降雪新增结冰物理、冰钓、禁钓或天气经济规则；美术地貌常驻雪峰与当次天气雪盖分层，东北不是永久下雪，秦淮不是永久下雨。

## 8. 坐姿、雨装、积雪与竿线漂

人物按[美术人物参考说明](../art-direction/README.md)的右岸坐姿、面左持竿继续设计；帽沿、脸侧、手肘、膝与坐石支撑必须能区分，蓑衣需灰面、墨线与飞白。不能整体旋转旧站姿冒充坐姿。
新坐姿显式定义座位支点、身体旋转支点、握竿点与局部关节；旧 `feetY=246` 不可偷偷改成坐骨。人物、坐石分层，坐石移位必须同步更新支撑几何。
共同的 pose 模型产出身体变换、握点、竿形与**实时 rodTip**；钓线起点消费该 tip，末端消费同一 bobberTopAt／sink 值，浮漂绘制、点击区与提示位置也消费同一锚点。绘制与求端点使用同一变换顺序。
待机、咬钩前倾、收竿回稳需核对整段连续性；现有状态以 idle／bite 为基线，新增收竿动作仅是后续映射建议，不声称已有状态机。视觉 pose 不得修改 catch 窗口或奖励结算。
雨装拆成蓑衣后片／身体／前片／帽沿，随身体和手臂变换，握竿手不能被抹掉。雪盖使用独立 snow-support-mask，附于帽顶、肩面及可选坐石上表面；脸、手、竿线与漂保持清楚。
积雪先采用有界、非持久视觉状态，消费 snowTarget；建议雪中渐入、雪停渐退，具体时长在样板评审后冻结。切区／重开按当前目标初始化，不继承上个景的雪量；不追算离线天气、不新增存档或真实积雪计量。

## 9. 三地样板、尺寸与运行预算

先按美术待审题材做 `dongbei` 黑龙江北极村、`jiangnan` 秦淮文德桥、`lingnan` 珠江沙面三样板，再扩其余九区。地点、取景与天气坐标仍须相应角色核实；渲染不把哈尔滨、南京／广州航线点自动代填为景点坐标。
三样板分别证明宽江冷林／阴雪、窄河桥檐／雨涟漪、宽江榕岸／不同水体；固定相同天气与时刻的无文字缩样仍应能区分。样板未获视觉评审不批量复制 12 张换色背景。

- 在真实客户端 420×350／640×490 量测 Pond 容器；不能把整窗误设为 1000×440 比例。检查浅／深桌面、DPR 1／1.5／2、阴雪低对比和夜间，人物不能糊成黑块，漂尾与钓线可追踪。
- 所有装饰／天气层 `pointer-events: none`；保留现有 onPoke、咬钩整场 onCatch、键盘 focus 与 no-drag 区。雨雪、前景和纹理不能截获点击或盖住反馈。
- `prefers-reduced-motion` 下减少／停止连续漂移、闪烁与密集粒子，保留稳定天气形态、人物服装、雪盖和明确鱼讯；不暂停 catch／travel／save 业务时钟。
- 使用单一受控视觉循环与有界粒子／事件池，避免每粒子 React setState／计时器；隐藏／最小化暂停纯视觉工作，卸载清理 rAF／监听／池，恢复不补发离屏期间全部撞击。
- 建议样板起测上限：雨粒子 64、雪粒子 48、同时接触效果 32；这些是渲染预算建议而非真实气象量。复杂前景不增加无限 DOM 或全屏重复 blur。
- 记录硬件、生产模式、帧耗时分布／CPU／内存、冷启动及纹理解码。60 Hz 下以 p95 帧耗时 ≤16.7 ms 为初始目标，实际低配门槛由验收冻结；未实测不得写“流畅”或已满足预算。
