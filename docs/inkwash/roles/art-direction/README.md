## 已明确的产品口径

- 水墨方向覆盖整个应用，包括顶部时钟、设置、出行、鱼篓与图鉴等界面；共用纸色、墨阶与淡彩反馈。文字、按钮、倒计时和状态仍由界面真实绘制，不能为了水墨效果变成不可交互图片。界面具体排版由 UI 角色继续定义。
- 顶部时钟始终显示 IP 现实所在地天气；游戏场景显示**当前游戏水域代表地点**的真实天气。两者是独立展示，不能在飞行后把顶部当地天气改成目的地天气。
- 抵达水域后展示该代表地点名称及当地天气；设置可以查看各水域天气，但查看本身不改变当前场景、出行状态或解锁记录。
- IP 识别时并行预取各水域天气，各水域独立缓存。并行数量、错误隔离、服务退避由天气/架构角色定义，美术角色不得用静态晴天底图代替请求结果。
- 这里提出的地标一旦获选，场景气象坐标必须落在同一地点附近，名称、地标、经纬度、缓存键一起交接。`REGION_LOCATIONS` 是既有航线代表点，**不得修改，也不得直接当新地标天气点**。例如漠河北极村不能使用哈尔滨天气，洱海不能沿用昆明，博鳌不能沿用海口。
- 本轮尚未逐点核实数字经纬度。交接清单必须把它们标为待地理/天气角色核实，不能凭记忆填数或用省会代填；坐标未核实的地标不能进入最终天气配置。

## 统一视觉规范（建议，待样板确认）

| 项目 | 规范及缩小后的检查方式 |
| --- | --- |
| 用笔 | 近岸与人物以干笔、侧锋、断续飞白组织轮廓；远山用柔边积染，水面以少量横向笔触表现。避免所有边缘同样清晰，避免用等宽描边把山石画成图标。 |
| 墨阶 | 保留五档关系：焦墨用于帽沿/握竿/近石关键边；浓墨用于近景体块；中墨用于衣褶和中岸；淡墨用于远山；极淡墨用于雾后轮廓。人物内部要留灰面和纸白，不能重新变成纯黑剪影。 |
| 留白 | 场景中部与浮漂周围低细节。以竿梢—钓线—浮漂为主要阅读路径，地区地标放到左侧或中远景侧翼。建筑不得围住浮漂，不为展示地标把整面水填满。 |
| 纸感 | 建议中性暖纸 `#F2F0E8`；纸纹单独一层，局部强度从约 2%–4% 起试，不做脏黄、裂纸或强噪点。纸纹只在场景裁切内显示，不能把桌面透明边缘填成矩形。颜色值是调色起点，非已经验收的色板。 |
| 淡彩 | 共用墨灰与少量赭石；水体与植被每区选一组低饱和主色。先用墨阶建立空间，再铺薄色，不用十二张同构图的换色图充当地区差异。下表的水色是风格化识别色，不表示该河全年真实水质颜色。 |
| 空间 | 近岸浓、远岸淡，至少三层距离；远山之间用透明度/墨色分离，不把固定白雾画成遮挡动态天气的不透明条。南北水域差异先体现在地貌、岸线、植物体块和建筑轮廓上。 |
| 小尺寸 | 当前场景坐标为 1000×440，不是整窗 420×350。至少检查 380、420、640 CSS 像素宽的场景缩样，最终以真实 Pond 容器量测为准。主轮廓在 420 宽下约 1.2–2 像素，细节约 0.8–1.2 像素起试；不能靠仅在母版可见的密集发丝、窗棂或雪粒表达主差异。 |
| 动态可读 | 咬钩首先通过浮漂下沉、竿梢弯曲、人物前倾传达；再由界面显示倒计时。天气粒子不能遮住漂尾与点击反馈，夜间保留帽沿/手/竿/漂的轮廓，不用整张素材乘黑后丢失人物。 |

## 三个优先样板的制作任务（尚未开始）

1. **黑龙江冷林大江**：先证明无雪、雨天、雪天三种情况下仍能认出北方宽江与林线；核查是否误用竹林、固定冰封或常驻极光。天气锚点须标漠河北极村。先交灰阶构图与人物尺寸稿，不交整套动画。
2. **秦淮桥河**：证明桥形、低屋檐与窄河空间在约 380 宽仍可识别，同时中央浮漂不被复杂建筑吞没。无需烘焙灯会、太阳或夜景光柱。天气锚点须标南京文德桥。
3. **珠江榕岸**：证明平缓宽江、榕冠和低矮历史建筑能与秦淮区别；不要靠整张图变绿。天气锚点须标广州沙面临江岸。

三个样板共用同一渔翁、同一浮漂/竿线交互基准、同一墨阶。每个样板先提交分层清单、灰阶缩样、淡彩缩样及地标引用，再进行视觉评审；通过后才扩展另外九区。当前不批量制作十二张成品。

## 人物、动作与晴雨雪装备

### 人物方向

主角色建议采用参考中的右岸坐姿、面左持竿、斗笠与可见衣褶。现有 Fisherman 是站姿剪影，不能用全局旋转现有站姿冒充坐姿。角色必须把帽沿、脸侧、手、肘、膝与坐石支撑关系画清；人物、石头与蓑衣之间有墨阶间隙。面部只作必要的轮廓，不堆细五官。

### 动作交接

| 状态 | 建议动作 | 必须稳定的锚点/分层 |
| --- | --- | --- |
| 待机 | 坐姿轻微呼吸，手保持握竿；衣摆仅有极轻变化 | 座位/坐石、手握点、竿根位置不漂移；不以整个人物上下晃动制造呼吸 |
| 咬钩 | 肩背前倾一点、手臂绷紧、竿梢受力弯曲、浮漂下沉 | 竿绕真实握点受力，线从实时竿梢接到实时浮漂；帽子与蓑衣跟随身体，不独立滑动 |
| 收竿/成功 | 手臂抬竿并短暂停留，再回待机；高品质反馈由既有交互另行配合 | 头、躯干、前臂、竿分开；不把鱼、金钱、弹窗烘焙进人物帧 |
| 错失 | 小幅垂肩或回头，随后回稳 | 不瞬间换掉角色面向，不跨越坐石，不重新摆放人物世界位置 |
| 无动作/减弱动态 | 提供清晰稳定待机帧 | 不依赖动画才能读懂手握竿与坐姿 |

本轮提出这些动作需要后续动作/渲染角色确认动画状态映射；当前游戏只有 idle/bite 等既有入参，不能在文档中假称全部动作已经实现。

### 装备与天气层

| 天气层 | 装备与材质建议 | 交接约束 |
| --- | --- | --- |
| 晴／多云基础 | 斗笠、淡灰布衣、鞋、鱼篓；蓑衣可作收拢的薄肩层，保持参考身份 | 基础身体不烘焙雨水、飞雪或强太阳描边；多云不能固定出现太阳倒影 |
| 雨 | 外披独立蓑衣层、加深的湿帽沿/肩背、少量帽檐滴水 | 蓑衣前后片分层，前臂可见；滴水和落水涟漪属于效果，不画死在衣服或岸边 |
| 雪 | 现有衣层外加保暖披肩/独立雪盖；帽顶、肩面、坐石上表面承接雪 | 角色雪盖遵循遮挡和接触面；不把脸、手和竿线刷成整片白色。积雪强度、消融速度是天气/玩法后续参数，当前未定数值 |

服装是统一角色的风格化设计，不宣称各地区传统服饰均一致。实际服务返回什么天气，场景就按其状态组合；不以地区固定套“海南永晴、东北永雪”。

## 场景几何与透明资源交接

### 已有事实基线

- `VIEW = 1000×440`，`HORIZON = 170`；地平线约占场景高 38.6%。地区底层沿用这一逻辑画布作为第一版对齐基准，不拉伸用户参考比例硬塞。
- 当前岸线 `SHORE_PATH` 从右侧进入，岸体、浅滩与石块在 scene.js 共用；人物当前基准为 `FISHER.x=866`、`feetY=246`、`scale=1.1`，握竿点 `(832,203)`，待机竿梢 `(575,128)`；浮漂为 `(528,338)`、露出高度 38。
- 这些是**当前站姿实现的数值**，不是已批准的新坐姿坐标。坐姿应新增明确的座位/地面/握竿锚点约定；不能把 feetY 偷换成坐骨位置，也不能在美术图里挪漂而保留旧点击热区。
- 目前 Pond 未接收 regionId，Fisherman 未接收天气装备。这里只规定交接需求；程序接线由相应角色实施。

### 推荐图层职责

| 顺序 | 资源/职责 | 透明、遮挡与动态限制 |
| --- | --- | --- |
| 1 | 纸感与动态天空 | 纸纹独立，天空由时间/天气层控制；地区景观资源的天空区必须真透明，不允许填白或固定蓝天 |
| 2 | 远山/远林 | RGBA，轮廓外透明，内部层次保持；不得自带太阳、月亮、星空、极光、固定云团或明显单向日照 |
| 3 | 中景地标/远岸 | RGBA，同尺寸对齐；岛屿、桥墩与岸线纳入水面遮罩，不使涟漪穿过陆地 |
| 4 | 水色/水墨细纹 | 可交独立的低饱和水色与纹理；不烘焙日月高光柱、会发光的晴天镜面或固定雨雪涟漪；天空反光由动态层控制 |
| 5 | 岸体/坐石/前景植被 | RGBA；岸石与人物分离，允许前后遮挡；植物不覆盖浮漂点击反馈 |
| 6 | 角色、装备、竿 | 透明底，分别交付；人物身体内部该保留的纸白是形体，不等于把身体挖空；周围原白底必须去掉 |
| 7 | 钓线、浮漂、涟漪、天气粒子、积雪 | 尽量沿用可控的动态层；不在景观或角色里重复画一套不可移动钓线、浮漂、雨滴 |
| 8 | 对话、咬钩提示与可交互界面 | 程序层，保持文本、倒计时、交互可访问性；不把按钮和小字画进图片 |

### 遮罩约定

所有遮罩与可见图使用同一画布、同一原点、同一版本；不能裁掉透明边再要求接手者猜对齐。`water-mask` 中白色为允许水面效果、黑色为天空/岸/岛/建筑，灰边只用于抗锯齿，不是水深。`shore` 岸线与 `horizonY` 要有独立几何标记，水面区域必须覆盖浮漂真实水线。

雨点击水、涟漪与动态反光要按 `water-mask` 裁切，不能在帽子、树干、屋顶、岸石上生成水圈。角色/竿/近景遮挡需有单独前景层；水面遮罩不承担整套人物动画遮挡。若设计积雪，应另交 `snow-support-mask` 表示可承接雪的上表面，不把它和水面遮罩混用。

雪峰、常年积雪等地貌可作为独立常驻自然层；当次天气积雪另作可开关层。这样晴天可以有远雪峰，却不会误显示正在下雪。动态天空、太阳、月亮及其水面反光**不得烘焙在任何地区底图**。

### 命名、母版与元数据

建议文件名为 `ink_{regionId}_{landmarkSlug}_{layer}_v001.png`；例如 `ink_dongbei_beijicun_farbank_v001.png`、`ink_jiangnan_qinhuai-wende_midlandmark_v001.png`、`ink_lingnan_shamian_foreground_v001.png`。共同角色用 `ink_fisher_{part-or-pose}_{weather-layer}_v001.png`。这些是待采用的资源规范，不表示文件已存在。

- 逻辑画布固定 1000×440；建议首版景观母版 2000×880，按同一倍数输出全部可见层和遮罩。不要把原参考的 16:9 当成成品要求。具体纹理尺寸/格式预算由渲染角色在样板测量后确认。
- 可见素材使用 sRGB、带真实 alpha 的 PNG 作为交接基准；透明背景不等于白底，不交 JPEG 角色 cutout。黑/白/棋盘三种底色检查边缘，避免白边和裁切残留。后续转 WebP 由打包流程决定，保留母版。
- 每个资源组附一份清单，至少记：`regionId`、地标 slug 与显示名称、版本、逻辑/像素尺寸、horizonY、岸线/水面 mask 名、人物支撑/握竿锚点、浮漂保留区、源文件、引用、导出者、评审状态。
- 天气/地理交接另记：`weatherAnchorName`、`latitude`、`longitude`、坐标系、坐标来源链接与核实时间、天气缓存键/版本；此处是设计字段建议，**不是要直接粘贴进程序的最终接口**。数字经纬度未核实就留空并标 pending，禁止复用航线点凑齐字段。
- 每次交付带灰阶/淡彩缩样和分层合成预览；预览可以显示模拟太阳帮助审稿，但必须明确是预览效果，生产底图中不带该太阳。

## 下一位 agent 的进入条件

当前只完成方向和分工。接手者应先确认这十二个题材是否采用，以及三个样板的坐姿、地标体量、中央留白是否符合用户参考；随后地理/天气角色核实同一地标的气象点，架构角色定义独立场景天气数据与资源清单，制作角色再开始小稿和素材。

视觉评审至少要看：三个优先样板的无文字缩样能否区分；人物是否有灰面与飞白；竿线漂是否连续；天空/日月能否独立关闭；地平线与水面 mask 是否对齐；雨滴是否只在水面起圈；雨雪装备是否与身体动作同步；时间/天气切换后是否仍有固定太阳或固定晴天倒影。**本轮这些项目均未验证，不应标记“已通过”。**
