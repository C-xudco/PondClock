日期：2026-10-23（Asia/Shanghai）。角色：需求分析 agent。基线：水塘时钟 1.1.1。

[水墨改版总入口](../../README.md)

本轮仅整理需求、现状差距、分工输入和后续验收条件，不制作资产、不修改游戏代码、不运行真实 IP／天气请求。下文的验收均为**待执行**，不是已完成功能。

## 1. 依据与解释边界

- 用户明确要求：全应用改为中国淡彩水墨风；优化现有渔翁；现有 12 地区分别有当地著名水域或景观；天气影响天空、雨雪、水面与人物。
- 用户指定案例：黑龙江阴天小雪应有云雪、没有太阳；秦淮雨滴落水产生涟漪，雪花落水消融，与雨的效果不同；人物雪天有积雪、雨天有斗笠蓑衣。
- 用户后续已确认：**顶部时钟保留 IP 现实所在地天气；场景使用游戏当前水域代表地点天气；识别本地 IP 天气时同时获取各水域天气；买机票抵达后标明该地地点名／地址与天气。** Leader 将有错字的“各水域”表述解释并记录为全部 12 区后台预取，本文件沿用该口径。
- 用户进一步明确“可以选择”指**在设置中查看各水域天气**。上方始终保留现实所在地；查看不扣票、不解锁、不改变 game.currentRegion 或当前场景，不是伪造天气或手动校正定位入口。
- （参考原图不包含在公开镜像，见版权说明）：已查看。淡青蓝远山、层叠水雾、大片留白水面、右侧浓墨竹石岸景、柔和淡金光色，作为配色、虚实与构图依据。图中太阳属于参考画面，不是所有天气都必须保留的固定素材。

### 不能误解的案例边界

- “黑龙江阴天小雪无太阳”是指定天气条件下的表现，**不是黑龙江永远下雪**；秦淮也不是永久雨景。
- 水墨风不等于把现有画面降低饱和度；需统一构图、笔触、层次和操作界面。
- 参考图中的阳光、白底、坐姿是视觉依据，不能覆盖实际天气、透明挂件适配及可读性要求。
- 12 区已有鱼群、机票、价格与存档引用，不因美术代表景点的选择而改区 ID 或经济规则。

## 3. 两地天气冲突：已确认的解决口径

### 3.1 原有语义与新增语义

原 README 与当前 Index/useClockWeather 的口径是电脑所在地天气，IP 坐标优先，缺坐标时使用 realRegion 或 homeRegion 的固定参考城市；机票目的地不改变天气。此前若仅凭“黑龙江当地天气”直接将全部天气改为游戏地点，会破坏原有桌面天气用途。

用户已选择双轨，因此**主天气来源不再是待选项**：

| 上下文 | 地点由谁决定 | 买机票／抵达影响 | IP／VPN 改变影响 | 显示要求 |
| --- | --- | --- | --- | --- |
| 顶部时钟天气 | 本次现实 IP 坐标；失败按既有规则显示缓存或参考点 | 不改变顶部地点 | 新有效 IP 可改变顶部地点 | 标明现实地点与联网／缓存／模拟来源 |
| 水塘场景天气 | game.currentRegion 对应的独立场景代表地点 | 到达后切换到新场景地点 | 不应跟着现实 IP 偷换游戏场景；IP 解锁仍按既有规则处理 | 标明游戏地区、代表地点名／地址和该地天气来源 |
| 12 区预取 | 每区独立场景地点 | 提前准备目的地天气，不能提前抵达或解锁 | IP 现实天气刷新时可触发后台预取 | 每区独立成功／失败／缓存状态，不能用现实天气填充所有区 |
| 设置天气查看器 | 用户选择查看的 12 区之一 | 只改变查看目标，不扣票、不解锁、不改变 currentRegion 或场景 | 顶部仍保持现实地点；查看器不校正 IP 定位 | 显示该区代表地点、天气、更新时间及来源，不提供手动伪造天气 |

**时钟的现实时间与季节是否需要为场景另算**尚无新增明确要求。现有 hour/season 取电脑本地时间；不要把天气双轨擅自扩大为新的游戏时间系统。

### 3.2 数据护栏：场景地点不能改航线地点

[regionLocations.js](../../../../src/data/regionLocations.js) 的 REGION_LOCATIONS 是当前航程／票价的固定代表城市坐标，不是已确定的钓鱼景点。即使东北美术最后选择漠河等地点，**也不能把原哈尔滨航线坐标改成该景点坐标**。

建议后续另建 sceneLocation 配置，记录 regionId、sceneId、地点显示名、地区／地址、天气坐标和坐标来源；与路由坐标分开维护。最终文件名和接口由架构角色设计，本阶段不创建配置实现。

### 3.3 缓存、失败与抵达时序要求

- 所有预取在后台进行，不阻塞本地读档、钓鱼、售鱼、购票或离线启动。
- 每区应按明确的 scene 地点及坐标隔离缓存；现实 IP 缓存和场景缓存语义独立。复用同一坐标的网络结果可以作为优化，但不能丢掉各自显示的地点归属。
- 实时请求失败可显示仍有效缓存；无有效缓存时明确使用场景模拟，不伪称已取得该地真实天气或编造温度。
- 到达后只接受当前地区、当前 scene 地点的结果，旧地点晚回调不能覆盖。建议出发后至抵达前仍用出发地场景，并利用预取准备目的地；旅行中画面策略最终由交互角色确认。
- “全部 12 区预取”包含尚未解锁区的天气准备，不因此授予到访、解锁、鱼获或金币。
- 新的请求并发量、总刷新预算、退避和服务配额应集中配置，继续尊重 429／Retry-After；本需求阶段不新增联网检测。
