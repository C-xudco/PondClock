# 水塘时钟：中国水墨改版协作入口

日期：2026-10-23（Asia/Shanghai）。产品基线1.1.1，Git基线`6685447`。本轮完成需求梳理、角色分工与交接设计；功能开发、素材制作和新版本验收在后续任务中分别留证，不将计划写成已经实现。

## 1. 用户确认的目标

1. 全应用统一为中国水墨画风。山水按用户淡彩参考，人物按斗笠蓑衣渔翁参考；提升笔触、结构、质感与小尺寸可读性。
2. 现有12个水域分别选一个有识别度的真实代表地点。地貌、建筑、植物、水色与水面形态都应有地域差异，秦淮与珠江不能只改名称、共用同一背景。
3. 上方时钟始终显示用户IP现实所在地的天气；水域场景显示游戏当前水域代表地点的真实天气，两者分别标地点和来源。
4. 联网识别所在地时，同步启动全部水域天气的后台预取，分地点缓存；部分失败不阻碍单机游玩。这里将用户带错字的“各区域天气都获取”按全部12区预取实现，具体请求形式由天气方案确定。
5. 买机票并抵达新水域后，场景切换到该水域代表地点及天气，在水域中展示地点名称/行政地址与天气。飞行期间保持在途语义，不能假称已经抵达。
6. 设置提供“查看各水域天气”。这是用户已选择的查看功能；顶部现实天气始终保留。查看其他水域不改变游戏位置、解锁或资产。
7. 真实天气驱动天空、降水、水面和人物。阴天小雪应无太阳，云随天气变化、雪花缓落并落水消融；小雨落水产生短促冲击和扩散涟漪。人物雪天有积雪，雨天有斗笠蓑衣。
8. 无边框悬浮、钓鱼交互、IP免费解锁、旅行网络、鱼价、七天保鲜、离线保存与自动记忆继续有效。不得用静态水墨图替换掉动态天气和核心玩法。

两处天气口径和“可以选择”的含义均已获用户明确回复。具体地标、人物姿态、笔触细节属于设计建议，先以三地样板对照参考评审，再扩展。

## 5. 关键工程约定

- 同一个天气状态驱动天空、太阳/月亮及倒影、粒子、水面和人物，避免“阴雪天仍有太阳/金色日光柱”。保留原始天气代码与强度，不把所有降雨都压成同一个“小雨”。
- 天空、山水、建筑、植被、岸、水面、人物、钓线/浮漂和天气分层；背景资产不能带固定人物、固定太阳或固定降水。雨雪落点必须共享场景水面遮罩，不能在天空或岸上生成水圈。
- 1000×440共用坐标与两档桌面尺寸作为现有约束；钓竿、钓线、浮漂端点使用同一几何来源。天气层不拦截点击，减少动态模式仍能辨认天气和鱼讯。
- 雪天积雪为表现状态，按受天气控制的视觉规则积累/消退；先不增加永久存档字段或真实积雪物理模型。冰封、雷电、季节落叶、音效另列扩展，不由示例自动扩大首批范围。
- 缓存/模拟/在线来源诚实区分；各地点独立缓存与错误，429尊重服务等待；所有地标素材本地打包，离线无需外部图片/CDN。
- 使用已有依赖先完成样板。引入大型渲染引擎、动画库、字体包等必须写明理由和预算，不以库堆叠替代视觉质量。
