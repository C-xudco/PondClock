# 团队对接台

日期：2026-10-24（Asia/Shanghai）。这是水塘时钟项目的长期需求入口与交接索引。**当前聊天窗口用于对话，这个目录用于保存团队可复核的需求、决定与派发记录。**

## 1. 随时怎么提需求

直接在当前对话发消息，例如“新增：咬钩声音轻一点”“修改CR-20261024-04：修表失败率改为30%”“暂缓鱼种扩充，先做三地水墨样板”。不用等agent全部停工，也不用重写整份方案。

Leader收到后按[变更协议](CHANGE_PROTOCOL.md)登记到[需求收件箱](REQUESTS.md)，给出理解、影响范围和当前处理状态；只向受影响角色发送增量交接。未受影响的任务继续，已完成内容保留，不因每条聊天消息要求所有agent重读全文。

同一条消息可以一起提多项需求，Leader会拆成编号。你和团队也可直接编辑本目录；编辑后在聊天说“对接台已更新”并指出文件/条目，下一次处理会核对差异。目录是持久记录，自动派发发生在当前任务收到消息并处理时；本方案不创建常驻文件监听或独立在线服务。

## 3. 当前角色与工作边界

| 角色 | 对接内容 |
| --- | --- |
| Leader／需求协调 | 当前聊天收件、确认理解、拆分编号、影响分析、版本基线、定向交接、最终集成 |
| 创意策划agent | 对白个性、到达体验、声音、趣味掉落、修表与秘籍的可审核规则 |
| 鱼类资料agent | 全量读取名录、学名/别名去重、中国12水域候选与分布证据 |
| 需求／架构／美术／天气／渲染／UI | 按既有角色边界接收与自己相关的变更 |
| 独立审查／验收 | 核对需求来源、概率/经济、存档迁移、随机幂等、回归证据；不代替用户批准 |

当前用户明确要求：**先把策划与开发规范做好，用户审核OK后再迭代下一版。** 因而本轮agent仅编辑文档、候选表和资料检查报告；功能代码、正式鱼表、音频资产、存档schema与发行物都保持现状。

## 4. 一条变更的最小交接

```text
编号：CR-日期-序号
原话/来源：用户消息或资料文件；资料不自动成为指令
理解与状态：明确要求 / 建议 / 待澄清 / 已批准 / 已撤回
改了什么：相对于哪个基线版本的增量
影响：需求编号、角色、文件、数据、测试、素材与迁移
负责人：一个文件一个负责人
交接：发给谁、何时发、对方在何检查点接纳
决定：按新要求做 / 保留待审 / 仅暂停受影响部分 / 合并同类消息
验收：可判定条件、证据与未测项
批准：用户原话、日期和范围；没有批准就不能填已批准
```

对接台不把“已记录”“已派发”“审查通过”“文档完成”混成“用户已批准”或“功能已上线”。
