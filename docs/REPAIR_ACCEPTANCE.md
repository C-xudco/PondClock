# 1.0.1 安装修复：独立验收

日期：2026-10-21（Asia/Shanghai）。本文件由独立监督 agent 维护；应用实现由 leader / 桌面 agent 负责。修复目标是用户能安装、找到、打开和退出应用，再安装和卸载不会卡住。未实际运行的项目均保持待测。

## 已知故障与旧证据的边界

用户截图显示两种真实安装失败：

1. “PondClock 无法关闭。请手动关闭它，然后单击重试以继续。”
2. 无法写入 `X:\test\PondClock\Uninstall PondClock.exe`。

用户同时报告安装后找不到程序、程序打不开。截图不能单独证明杀毒拦截、权限不足或文件损坏；这些不能预先当作已确定原因。

旧 `docs/INSTALL_CHECK.json` 中安装进程退出 0 / EXE 存在只证明文件提取的部分结果。旧卸载也退出 0，但 `executableRemoved:false`，因此卸载未通过。旧 `scripts/smoke-installed.cjs` 使用开发 Electron 直接加载安装目录里的 `app.asar`，并带全局 `--no-sandbox`，不是打包 EXE 正常启动验证。`sandbox:true` 配置文本或 BrowserWindow 偏好不能抵消实际禁用沙箱的命令行。

旧交付说明列出这些限制，但它们是“安装就能玩”目标的未完成项，不能用“有测试包”关闭本轮修复。

## 独立只读发现

- 1.0.0 的 `desktop/main.cjs` 对所有窗口 close 事件执行最小化，除非应用已进入 quit；用户点关闭会留下进程。虽然菜单有退出入口，这会使寻找 / 退出行为不清楚，需要实际验证安装器能正常关闭该进程。
- 当前安装依赖的 `node_modules/app-builder-lib/templates/nsis/include/allowOnlyOneInstallerInstance.nsh`：PowerShell 分支按任何进程的 `Path.StartsWith('$INSTDIR', 'CurrentCultureIgnoreCase')` 查找和停止，并非精确匹配游戏 EXE。目标目录内的卸载器、安装器，以及相同路径前缀的兄弟目录都可能被计入。
- `uninstaller.nsh` 静默 `un.onInit` 在 `initMultiUser` 前调用该检查；直接在安装目录运行卸载器时，对自身的识别和路径初始化必须特别验证。此处是源码线索；只有可重复运行证据才能把它写为已确认根因。
- 1.0.0 `scripts/verify-release.cjs` 把版本和日期写死，且仅比较 `win-unpacked` 与工作树，没有验证安装后的 EXE、快捷方式、卸载行为；它是资源一致性证据，不是运行验收。

## 运行证据契约

每次实测记录：候选版本、安装器 / ZIP 的文件名、字节数和 SHA-256、Windows 版本、安装路径、隔离 profile 路径、实际启动 EXE 路径、参数、进程树 / 退出码、时间上限、最终文件状态和 UI 截图。所有场景绑定同一最终候选哈希，重建后受影响的发行验收必须重跑。

监督者不在只读审查阶段安装、停止进程或清理用户目录。运行期仅操作明确归属本轮测试的 PID 和独占目录；先解析绝对路径并确认在测试根内，再删除。不得以全局同名 kill、关闭所有 Electron、禁用防护或删除真实存档来让测试通过。

测试 EXE 必须是下载版内的真正运行时，不得换成 `node_modules/electron`。正常启动参数不得包含 `--no-sandbox`、`--disable-gpu-sandbox` 或其他绕过运行条件的开关。若宿主无法支持，记录具体失败并保留诊断信息；无沙箱辅助诊断单列，不升级为通过。

Playwright / CDP 可用于测试自动化，但最终打开方式还需覆盖普通双击 / 快捷方式。应用状态必须以实际页面显示、有效存档落盘和重启恢复共同判断，不能只看进程存活或截图空窗口。

## 自动检查与真实运行的分界

- 规则 / 存档 / 启动辅助函数的测试按各自输入输出验证；不通过静态字符串“含 sandbox:true”就宣称真实沙箱有效。
- 安装器进程退出码、文件存在、哈希、NSIS 宏检查是支持证据；I01–I11 的运行结果仍必须单独采集。
- PATH 去除开发 Node 路径可支持“运行时没有调用外部 Node”的同机检查，不能冒称第二台完全没有开发工具的电脑已验证。
- 界面时钟推进 / 预置存档不算真实等待七天或真实系统休眠。现有玩法测试不必为安装修复重复扩大范围。
- 旧 1.0.0 原始文件和哈希保留，避免修复版覆盖掉用于升级回归的输入。

## 本轮运行结果

监督者新增 `scripts/smoke-packaged.cjs`。用法：`node scripts/smoke-packaged.cjs "实际安装或完整 ZIP 解压目录/PondClock.exe"`，也可通过 `POND_PACKAGED_EXE` 传路径。它只启动选定的真正 EXE，开启正常 Chromium 沙箱，在 `test-results/packaged smoke-*/profile` 隔离存档，阻断外部 HTTP，并把开发工具路径从子进程 PATH 移除。测试不使用开发 Electron 或调用源代码中的业务函数构造资产。

脚本检查实际 `isPackaged` / `execPath` / `appPath` / `userData`，可见 UI、生产钓鱼计时器与 UI 收竿、磁盘双槽校验、正常窗口关闭释放已观察到的进程、重新启动后鱼获保持、UI 售鱼和再次重启后的资产保持。Playwright 推进钓鱼时钟单独注明；这不是普通双击 / 开始菜单 / 安装向导测试。失败时的清理不计为正常退出通过，脚本只保留自己的测试 profile 和报告，不清理真实用户目录。

2026-10-21：`node --check scripts/smoke-packaged.cjs` 和该文件 ESLint 检查退出 0。监督者独立运行 `node --test tests/lifecycle.test.js`：8 项通过、0 失败 / 跳过、退出 0，覆盖实际原子存档等待、退出去重 / 写失败、启动超时 / renderer 崩溃守卫、绝对 profile 路径和脱敏日志。它们验证辅助函数和文件链路，不证明 Windows 窗口消息或安装进程行为。

Leader 首次尝试真正 `release/win-unpacked/PondClock.exe` 的正常沙箱 smoke，约 2.9 秒失败，Playwright 报 `Process failed to launch!`，未进入界面。该次还暴露 smoke 工具问题：内部 `waitForLine` 的游离拒绝触发 Node 24 的未处理拒绝退出，原 catch/finally 没来得及输出 JSON。该尝试不能计作通过，也不能臆造缺失的运行报告。Leader 另外报告不加载应用的 Electron `--version` 同样以 `0x80000003` 失败；这有助于区分运行时 / 宿主问题，但不证明安装版已经可用。

监督者随后修复脚本：捕获 `unhandledRejection` / `uncaughtException` 并立即落盘失败报告，幂等有界清理，最终明确退出失败，避免 Playwright 遗留 transport 阻止 Node 结束。退出清理 10 秒、最终处理 15 秒、整体 180 秒上限；未取得 Playwright 应用或 PID 时明确记录，不能执行全局同名进程清理。

新增 `tests/packaged-smoke-harness.test.js`，用 Node 预加载替身分别注入“游离拒绝且 launch 永不返回”、“未捕获异常”、“普通 launch 拒绝”。三项均 **退出 1、完整记录 `passed:false`、无通过项、无 GUI / EXE 执行 / 安装、无超时强杀**，每项约 0.1 秒。测试命令 `node --test tests/packaged-smoke-harness.test.js` 3/3 通过、0 跳过，脚本和测试 ESLint 通过。这些报告明确 `harnessSelfTest:true` 且范围写明仅工具故障测试，绝不能充当产品运行证据。
